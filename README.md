# 媒探 MediaSniff

装完即用的网页视频嗅探与下载扩展。**直下 / HLS 合并 / DASH 合并全部在浏览器内完成，无付费墙，全程本地处理。**

---

## 核心特性


| 能力                 | 说明                                                                                                                   |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **多协议嗅探**       | 网络层`webRequest` 观察 + DOM 扫描双路并行；自动解析 `m3u8` / `mpd` 变体并归并去重                                     |
| **直链下载**         | 原生下载（Cookie 自动携带）优先；需自定义`Referer` 的站点自动降级为扩展内抓取（DNR 补头 + Offscreen 落盘）             |
| **HLS 合并**         | 分片浏览器内下载，用内置`mux.js` 转封装为 MP4，无需任何外部程序                                                        |
| **DASH 合并**        | 自研 fMP4 box 级拼接器合并音视频双轨；AES-128 用 WebCrypto 在浏览器内解密                                              |
| **断点续传**       | 分片级续传 + 指数退避重试；失败保留已下载数据，重试不从头开始                                                          |
| **音频智能命名**     | 音频默认输出**MP3（192kbps）**——裸音频流无容器歧义，彻底规避被 Chrome 误判为 `.mp4` 的问题；可在设置切回「保留原始」 |
| **子目录落盘**       | 下载文件统一存入`MediaSniff/` 子目录，不污染下载根目录                                                                 |
| **侧边栏 UI**        | 常驻 Chrome 侧边栏（Side Panel），切换标签自动刷新；浅/深双主题                                                        |
| **本地引擎（可选）** | 重编码/转码等重负载任务可路由到独立桌面程序（Native Messaging）；不装也能完成所有合并类任务                            |

**不做的事（定义性边界）**：不绕过 DRM、不针对禁下平台适配、不采集浏览数据、无会员/订阅/许可证。

## 环境要求

- **浏览器**：Chrome / Edge **114 及以上**（Manifest V3，依赖 Side Panel / Offscreen 能力）
- **构建环境**：Node.js 18+、npm

## 从源码构建

```bash
# 1. 安装依赖
npm install

# 2. 类型检查 + 构建到 dist/
npm run build

# 3. 打包为可安装 zip（生成 mediasniff-v1.0.0.zip）
```

| `npm run test`  | 运行单元测试（Vitest）                      |
| `npm run icons` | 重新生成工具栏图标                          |

## 安装方式

两种方式任选其一：

### 方式 A：加载已解压目录（开发/调试推荐）

1. 打开 `chrome://extensions`，右上角开启 **开发者模式**
2. 点击 **加载已解压的扩展程序**
3. 选择本仓库构建产物目录 **`dist/`**
4. 改代码后点扩展卡片上的 **↻ 重新加载** 即可生效

### 方式 B：拖入 zip 包

将 `npm run zip` 生成的 `mediasniff-v1.0.0.zip` 直接拖入 `chrome://extensions` 页面。

> 想确认浏览器实际加载的是哪一版？打开扩展侧边栏 → 顶栏 📄 **运行日志** 页底部显示「当前版本构建于 …」（构建时间已注入产物）。

## 使用指南

1. **打开侧边栏**：点击工具栏的媒探图标，或右键图标选择「在侧边栏中打开」。
2. **浏览含媒体的页面**：访问有视频/音频的网页，媒探自动嗅探，工具栏图标角标显示检出的媒体数量。
3. **查看列表**：侧边栏「下载器」标签列出所有嗅探到的媒体，含清晰度/格式/大小；可展开变体、筛选、搜索、批量选择。
4. **下载**：点击单条或批量操作的「下载」，文件落入 `MediaSniff/` 子目录。进度在「任务」标签实时可见。
5. **运行日志**：顶栏 📄 进入，可查看脱敏日志、按级别过滤、导出，用于排查下载/合并问题。

### 音频输出设置

设置 → **音频输出**：

- **转为 MP3（默认）**：AAC→MP3 二次编码（有损），兼容性最好（车载 / U 盘 / 剪辑软件）。
- **保留原始**：无损保留站点原始格式（m4a 等）；但部分站点（如 QQ 音乐）的音频会被 Chrome 按内容判成视频而改名为 `.mp4`，遇到时请切回「转为 MP3」。

## 技术栈与架构

- **构建**：Vite 6 + TypeScript 5.8（strict）、`target: chrome109`
- **UI**：React 19（侧边栏 / 弹窗），`data-theme` 双主题
- **媒体处理**：`mux.js`（HLS→MP4 转封装）、`lamejs`（MP3 编码，随包内置）、WebCrypto（AES-128 解密）
- **MV3 多入口**：`background`（Service Worker，嗅探/调度/下载）+ `content`（隔离桥）+ `offscreen`（重封装/合并/落盘）+ `popup`（React）

### 状态持久化


| 数据     | 位置                | 说明                                      |
| -------- | ------------------- | ----------------------------------------- |
| 任务     | `storage.local`     | 扩展重启后置于「暂停」，可续传            |
| 媒体集合 | `storage.local`     | 导航/刷新后保留                           |
| 分片     | IndexedDB           | 下载成功后即清理；失败/暂停保留以支持续传 |
| 日志     | 内存环形（1000 条） | 仅本地，可导出                            |

## 本地引擎（可选，非必需）

重编码 / 转码 / 本地文件转换等 CPU 密集型任务由独立桌面程序 **mediasniff-engine**（Node + ffmpeg + Native Messaging）承担。扩展已内置其全部对接面（四态探测、安装引导、命令路由）；**未安装本地引擎时，所有合并类任务仍可在浏览器内完成**，仅转码类不可用（按合规引导提示，不静默降级）。

---

## 隐私与合规

- **全程本地处理**：嗅探、合并、解密均在浏览器内完成，不上传任何媒体数据。
- **无远端上报**：所有埋点/日志仅存于本地，承诺不采集浏览行为。
- **合规边界**：不绕过 DRM、不针对禁下平台做适配。这是产品定义的一部分，而非待优化项。

---

## 已知边界

- fMP4 双轨合并采用顺序轨拼接 + track 重编号，**未做轨道交织**；主流播放器（VLC / Chrome / mpv）可播，极端播放器兼容性待真实站点回归。
- 未实现 HLS `BYTERANGE`、DASH `SegmentBase(sidx)`；遇到时降级为直接下载并记录日志。
- 直播流（无 `ENDLIST` / dynamic）按产品定义**不支持**。
- 页面主世界探针（fetch/XHR/MSE 包装）因实测会导致部分大厂站点播放器检测环境被篡改而拒绝播放，已停用；嗅探能力无实质损失。
