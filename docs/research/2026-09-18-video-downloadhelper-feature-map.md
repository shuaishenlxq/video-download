# Video DownloadHelper 功能全景调研与会员功能剥离分析

> 调研日期：2026-09-18
> 调研对象：Video DownloadHelper（downloadhelper.net），Chrome / Firefox / Edge 扩展，版本基线 v10.5.2.2
> 调研目的：为自研插件「MediaSniff」确定功能基线，剥离会员（Premium）相关能力，保留核心的视频资源嗅探与下载能力
> 资料来源：官方站点与 FAQ、官方文档站、Chrome Web Store 条目、配套程序开源仓库（aclap-dev/vdhcoapp）架构文档、第三方使用评测

---

## 一、产品形态总览

Video DownloadHelper 是「**浏览器扩展 + 本地配套程序**」的双体架构，二者能力边界清晰：

| 组件 | 技术形态 | 承担能力 | 安装要求 |
|------|----------|----------|----------|
| 浏览器扩展 | MV3 扩展（Chrome / Edge）<br>WebExtension（Firefox） | 媒体嗅探、列表展示、任务编排、参数设置、调用下载 | 必装 |
| 本地配套程序 `VdhCoApp` | Node.js 桌面应用，通过 **Native Messaging** 与扩展通信（JSON-RPC over stdio） | 音视频合并（mux）、格式转换（ffmpeg）、文件系统读写、调用本地播放器 | 选装，装后能力全开 |

**关键事实**：**不装配套程序时，扩展只能直下「服务端已提供完整文件」的媒体**；HLS/DASH 的分片合并、音视频分离轨合并、以及任何格式转换，都必须依赖配套程序。这是原产品最重要的架构约束，也是自研方案的差异化切入点。

配套程序内部模块（据其开源仓库架构文档）：

| 模块 | 职责 |
|------|------|
| `main.js` | 进程入口、命令行参数（install / uninstall / --info / --version） |
| `native-messaging.js` | Native Messaging 协议实现 |
| `weh-rpc.js` | RPC 通信层（JSON-RPC 分发） |
| `converter.js` | 调用 ffmpeg 做媒体转换 |
| `file.js` | 文件系统操作（读写、目录、文件选择器） |
| `downloads.js` | 下载任务管理 |
| `request.js` | 网络请求 |
| `vm.js` | JS 执行环境 |
| `native-autoinstall.js` | 向各浏览器注册 Native Messaging manifest |

注册路径（跨平台）：Windows 走注册表 `HKCU\Software\...\NativeMessagingHosts`；macOS 走 `~/Library/Application Support/<浏览器>/NativeMessagingHosts/`；Linux 走 `~/.mozilla/native-messaging-hosts/` 等。

## 二、完整功能清单（按模块拆解）

### M1 媒体嗅探与检测

| 编号 | 功能 | 行为细节 |
|------|------|----------|
| M1-1 | 网络请求嗅探 | 监听页面发起的媒体请求，识别 MP4 / WebM / MOV / FLV / MKV / MP3 / M4A / AAC 等扩展名与 MIME |
| M1-2 | 流式清单识别 | 识别 HLS（`.m3u8`）与 DASH（`.mpd`）清单文件 |
| M1-3 | 页面媒体元素扫描 | 扫描 `<video>` / `<audio>` / `<source>` 标签的 `src` / `currentSrc`，含 iframe 内嵌 |
| M1-4 | 图标状态驱动 | 检测到媒体 → 工具栏图标由灰变彩并播放动效；区分「无媒体」「已检测到媒体」等状态 |
| M1-5 | 媒体条目归并 | 同一媒体的多个分片 / 多次请求归并为一条记录，按 URL 模式与元数据聚类 |
| M1-6 | 元数据补全 | 标题、时长、文件体积、缩略图 / 首帧预览、分辨率、格式 |
| M1-7 | 媒体类型分类 | 视频 / 音频 / 图片三类可切换（Images / Videos / Links 筛选按钮） |
| M1-8 | 域名黑名单 | 将指定域加入黑名单，隐藏该域检测到的媒体（用于屏蔽广告位视频） |
| M1-9 | 检测过滤器 | 按最小/最大体积、扩展名、类型等条件过滤，减少噪音 |
| M1-10 | 分标签页归属 | 每个标签页维护独立媒体集合，切换标签页展示对应结果 |

### M2 媒体列表与选择（Popup 界面）

界面为「**Video Downloader / Setting / Log**」三标签页结构。

| 编号 | 功能 | 行为细节 |
|------|------|----------|
| M2-1 | 媒体列表 | 每条展示缩略图、标题、时长、体积、格式、质量徽标 |
| M2-2 | 清晰度变体展开 | 条目可展开查看该媒体的多个分辨率 / 码率版本（如 240p~4K） |
| M2-3 | 音视频分离轨展示 | DASH 场景下音轨与视频轨分别列出，供合并 |
| M2-4 | 搜索 | 按文件名 / 时长（如输入 `10:30`）/ 体积（如输入 `150`）检索 |
| M2-5 | 排序 | 按体积（默认降序）、分辨率、检测时间排序 |
| M2-6 | 批量选择 | 勾选多条媒体，执行批量下载 |
| M2-7 | 单条操作 | Quick Download / Download / Download & Convert / 复制地址 / 预览播放 |
| M2-8 | 加密标记 | 标注流是否为加密流（影响可下载性） |
| M2-9 | 空状态引导 | 无媒体时提示「请先播放页面中的视频以触发检测」 |
| M2-10 | 下载进度展示 | 列表内实时显示下载进度、合并进度（Loading FFmpeg → Downloading → Merging） |

### M3 下载引擎

| 编号 | 功能 | 行为细节 |
|------|------|----------|
| M3-1 | 渐进式直下 | 直接下载服务端提供的完整媒体文件 |
| M3-2 | 带请求头下载 | 附带 Referer / Origin / Cookie 等头，绕过防盗链 |
| M3-3 | HLS 分片下载与合并 | 解析 m3u8 → 拉取全部分片 → 合并为单一文件 |
| M3-4 | DASH 音视频分别下载与合并 | 视频轨与音频轨分别拉取后封装合并 |
| M3-5 | 加密流处理 | AES-128 加密 HLS 可取密钥解密；SAMPLE-AES / Widevine 等 DRM 无法处理 |
| M3-6 | 自适应码率选择 | 解析 master playlist 的 variant 列表，供用户选择清晰度 |
| M3-7 | 断点续传 | 下载中断后可恢复（依赖配套程序的文件分块与校验） |
| M3-8 | 并发控制 | 可设置最大并发下载任务数 |
| M3-9 | 保存目录与命名 | 默认目录（`~/dwhelper` 等），支持命名模板（`[title].[ext]`、`[title]-[resolution].[ext]`） |
| M3-10 | 询问保存位置 | 可选在下载前弹出「另存为」对话框 |

### M4 媒体处理（合并与转换）—— 全部依赖配套程序

| 编号 | 功能 | 行为细节 |
|------|------|----------|
| M4-1 | 音视频聚合（mux） | 将分离的视频轨与音频轨封装进同一容器，**不重新编码**，保留原始流 |
| M4-2 | Quick Download | 按默认设置一键下载（可命中转换规则） |
| M4-3 | Download | 下载前弹出参数面板，可选输出格式与目标目录 |
| M4-4 | Download & Convert | 下载后自动转换；可勾选「默认使用此动作」 |
| M4-5 | Convert local files | 对**已存在于本地**的媒体文件执行转换 |
| M4-6 | 输出预设 | 内置输出预设（profile）列表，覆盖常见设备/用途场景 |
| M4-7 | 输出参数微调 | 「Configure output details」进入详细参数页，可调容器、编码、码率等 |
| M4-8 | 预设管理 | 内置预设不可修改；可 Duplicate 复制后修改，可 New 新建、Remove 删除、重命名 |
| M4-9 | 转换规则 | 按**文件扩展名**或**来源域名**匹配，自动对匹配的下载执行指定转换；规则自上而下顺序匹配、命中即止 |
| M4-10 | 引擎检测 | 转换页可 Recheck converter 重新检测配套程序状态 |
| M4-11 | Linux 兼容 | 优先调用 `avconv`（Libav） |

### M5 设置项

| 分组 | 设置项 |
|------|--------|
| General | 配套程序安装状态与二进制路径、UI 语言（29 种，含简体中文 / 繁体中文）、主题 |
| 检测 | 域名黑名单、检测过滤器、检测灵敏度 |
| 下载 | 最大并发下载数、命名规则、保存目录、是否询问保存位置 |
| 转换 | 默认转换格式、转换质量、转换规则、Recheck converter、Advanced 开关 |
| 日志 | Log 标签页展示运行日志 |
| 隐私 | 声明不采集浏览数据、无跟踪 |

### M6 明确的能力边界（原插件自述的限制）

| 限制 | 原因 |
|------|------|
| Chrome 版不支持 YouTube | Google Web Store 政策限制（Firefox / Edge 版可用） |
| DRM 受保护内容（Netflix / Prime / Disney+ 等）无法下载 | 平台 DRM 保护，非技术可绕过项 |
| 部分站点需先播放视频才能检测 | 媒体由 JS 动态拉流，静态扫描抓不到 |
| 严格 CORS 站点预览 / 时长提取失败 | 跨域限制（下载本身仍可用） |
| 复杂流协议与转换必须装配套程序 | 浏览器沙箱无对应能力 |

## 三、会员（Premium）功能剥离分析

原产品采用「免费版 + 一次性买断 Premium 许可证」模型，官方自述 **Premium 包含**：解锁无限下载、更快的处理速度、转换产物去水印、高级下载功能、支持项目持续开发。据此逐项剥离：

| 编号 | 会员相关能力 | 原产品表现 | 剥离决策 | 理由 |
|------|-------------|-----------|----------|------|
| P-01 | 下载额度限制 | 免费版存在下载数量/转换次数限制，Premium 解锁无限 | **移除** | 自研产品不做商业化，无额度概念，直接全量开放 |
| P-02 | 转换产物水印 | 免费版转换输出带水印，Premium 去除 | **移除** | 不设付费墙，输出恒为无水印 |
| P-03 | VIP Server 远程解析 | 输入 API Key 启用服务端远程解析复杂链接 | **移除** | 依赖远端服务与账号体系；改为纯本地解析链路 |
| P-04 | 许可证购买 / 激活 / 找回 | Premium 页、激活入口、Restore purchase | **移除** | 无账号与授权体系 |
| P-05 | 服务端加速处理 | Premium 优先处理，免费版排队/限速 | **移除** | 无服务端，全部本地执行 |
| P-06 | 跨浏览器许可证同步 | 一份许可证在 Chrome / Firefox / Edge 通用 | **移除** | 无许可证概念 |
| P-07 | Rapid Release 抢先版通道 | 付费用户可加入快速迭代通道 | **移除** | 无分级发布计划 |
| P-08 | 升级引导 UI | 界面内的 Premium 入口、升级提示、付费角标 | **移除** | 界面对应位置留空或替换为「关于」 |
| P-09 | 账号注册 / 登录 | 官方称无需注册，但 Premium 需绑定 | **移除** | 全程无账号，纯本地 |

### 剥离后的能力净集（自研产品基线）

```
保留并强化的核心能力
├── 媒体嗅探（网络层 + 页面层双路）
│   ├── 渐进式媒体文件识别
│   ├── HLS / DASH 流式清单解析
│   ├── 页面 video/audio 元素与 MSE 拉流捕获
│   └── 元数据补全（标题/时长/体积/缩略图/分辨率）
├── 媒体管理（列表 / 筛选 / 搜索 / 排序 / 批量选择）
├── 下载执行
│   ├── 带凭证直下（Referer / Cookie / Origin）
│   ├── 分片拉取与合并
│   ├── 加密流解密（AES-128）
│   └── 并发控制 / 重试 / 续传
└── 媒体处理（合并 + 转换体系完整保留，但无付费墙）
    ├── remux 合并封装（不重编码）
    ├── 下载并转换 / 本地文件转换
    ├── 输出预设管理 + 参数微调
    └── 转换规则（按扩展名 / 域名自动触发）

不做的
├── 会员 / 订阅 / 许可证 / 账号体系
├── 远程解析服务端
└── DRM 绕过（技术不可行，且合规红线）
```

## 四、对自研方案的关键启示

1. **原产品的架构约束是真空档位**：HLS/DASH 合并强依赖本地配套程序，导致「装扩展 ≠ 能用」。自研方案若能在浏览器内完成 remux 合并，即可做到「零安装可用」，这是最直接的体验优势。
2. **嗅探不能只靠网络层**：现代站点大量使用 hls.js / dash.js 在 JS 内拉流后喂给 MSE，纯网络监听会漏。必须叠加页面上下文探针。
3. **转换体系可以完整保留，但要有能力降级**：格式重编码是 CPU 密集任务，浏览器内方案（WebAssembly）性能远低于原生 ffmpeg，需要双通道设计——浏览器内做免重编码的封装合并，本地引擎做真正的转码。
4. **合规边界必须在产品层面固化**：DRM 与平台政策限制不是「待优化项」，而是明确的能力边界，需要在文档、界面提示、首次使用声明中三处体现。
